# 报告模板（`report_md` 四部分）

`report set` 只检查结构、必需字段、结论枚举与证据引用是否落在当前证据包及声明的补充证据之内，不认证结论正确。下面每个方括号都要替换成实际内容或"未知"。事实与推断分层写，推断加"（推断）"。不写百分比，不写"真招概率"。四个二级标题必须逐字使用，不加编号。

```markdown
# [岗位标题] — [公司显示名]（[job_id]）

证据包：[bundle_id]（采集完整度：complete/partial）· 画像版本：[profile_revision] · 生成时间：[UTC]

## 招聘信号判断

### 事实清单
- [事实 1，标 evidence_id。观察类事实只写首末观察日期、观察次数与覆盖限制，例：本工具在 2026-08-30 与 2026-09-14 之间共观察到该岗位 4 次，覆盖仅限本工具的搜索（ev_…）]
- [事实 2，例：详情页 JSON-LD 声明值为 2026-09-01（ev_…），语义未核验，不当作发布日期]
- [事实 3，例：公司页显示 BOSS 数 3、在招岗位 41（ev_…，快照时间 …）]

### 支持信号（与所选倾向有关的支持线索）
- [线索 + evidence_id + 它为什么支持你在下方选择的倾向]
（没有就写：本次未取得支持线索。原因：[缺哪类证据 / 站外工具不可用]）

### 反对信号（对所选倾向的质疑线索）
- [线索 + evidence_id + 它为什么让所选倾向变弱；可以用来质疑当前招聘意向，但要和展示持续性分开说]
（没有就写：本次未取得反对线索。没有反对线索不等于反对证据不存在。）

### 未知项
- [未取得的证据类型，及它会如何改变判断]

### 定性倾向（推断）
**[倾向真实在招 / 倾向长期挂岗 / 证据不足]**（推断，基于本证据包与上述时间点；不是岗位真假认证，不能作为自动排除条件）
- 展示持续性：[只根据离散观察日期与次数说明，不把离散观察概括成连续展示]
- 当前招聘意向：[单独一句，引用证据或写未知]
- 支持与反对两侧都没有线索时，这里必须是"证据不足"。

## JD 翻译

| 原句 | 解释（用用户能懂的话） | 证据或假设 |
|---|---|---|
| [JD 原句] | [解释] | [evidence_id，或以"假设："开头的一句话] |

## 不匹配点

| 岗位要求 | 画像现状 | 严重程度 | 证据或假设 |
|---|---|---|---|
| [要求] | [现状，来自 profile] | [high / medium / low / unknown] | [evidence_id，或以"假设："开头的一句话] |

## 简历建议

### 已证实经历如何表达
- [只能用 profile 里已有、用户自述的经历；改的是表达，不是内容]

### 要达标还需补的行动
- [列行动，不把这些能力写成已有经历]
```

## 结构化字段与 Markdown 的对应

`authentic.facts/supporting/opposing/unknowns/conclusion` 对应"招聘信号判断"；`jd_translation.sentences`（每项有 `evidence_id` 或非空 `assumption`）对应"JD 翻译"；`mismatches`（`requirement`、`profile`、`severity`，以及 `evidence_id` 或 `assumption`）对应"不匹配点"；`resume_advice.proven/to_reach` 对应"简历建议"。两边内容必须一致，CLI 只查结构，一致性靠你。
