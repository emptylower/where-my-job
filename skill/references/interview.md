# 建立求职画像

目标：用最少的来回拿到写 `profile.json` 与 `scoring.json` 所需的信息。先说 SKILL.md 铁律 4 的边界告知，用户确认后再开始。对用户只说问题和画像要点，不提文件名、字段名与校验。

## 第一步：问有没有简历

用选择题问（有结构化选择工具就用，没有就给编号选项）：

- 有简历文件：请用户给出文件路径，或把文件拖进对话。你读完后起草下面每一项，再逐项确认。
- 没有或不想给：直接进入第二步，每题给常见选项，另留"其他"。

读简历时只提取求职需要的内容：做过的方向、年限、技能、所在城市。联系方式、证件号、住址、照片不写进画像。简历写得模糊的地方不要替用户补全，放进确认题里问。

## 第二步：逐项确认（一次一题，选项不超过 4 个，另留"其他"）

| 项 | 怎么问 | 写入 |
|---|---|---|
| 目标方向 | 多选。有简历时给 2-4 个从简历推断的方向，最贴近的标"推荐"；没有简历时请用户直接说。再问优先级。 | `profile.targets.directions`；同时决定 `scoring.classify` 的顺序 |
| 城市 | 多选：简历里的所在城市、用户提到过的城市、"不限城市"。 | `profile.targets.cities`；选"不限城市"或没说就写空数组，面板显示"未限定城市"，不要猜 |
| 经验范围 | 多选，四个选项对应固定档位："应届 / 在校 / 经验不限"对应 `经验不限`、`在校生`、`应届生`；"3 年以内"对应 `1年以内`、`1-3年`；"3-5 年"对应 `3-5年`；"5 年以上"对应 `5-10年`、`10年以上`。有简历时按工作年限标"推荐"。 | `profile.targets.experience_scope`；同一列表写入 `scoring.experience_allowlist`，并决定策略里的经验筛选码 |
| 技能与自评 | 只确认与目标方向最相关的 4-8 项，每题一项技能，选项：了解 / 能独立完成工作 / 熟练。有简历时按简历里的证据标"推荐"。 | `profile.skills`，每项 `{name, level}`；`level` 只能是 `familiar`（了解）、`working`（能独立完成工作）、`proficient`（熟练） |
| 红线 | 多选：外包或驻场、频繁出差、学历要求高于自己、其他。 | `profile.redlines`；再转成 `scoring.exclude`，每条要有 `reason` |

技能等级是用户自述，不是能力认证；不收数字打分。结构化选择工具一次最多问 4 题时，把技能分批问。

## 非必答（用户不提就留空，不追问）

薪资底线、离职原因、当前在职状态、健康与家庭情况、任何"不会写在简历里的秘密"。这些留空不影响流程；需要时在报告里写"用户未提供"。

## 校园岗位政策：不单独提问

校园政策只写在 scoring 的 `campus_policy`，默认 `auto`，由经验范围推导。经验筛选码与 `scoring.experience_allowlist` 两处取并集：

| 用户选的经验范围 | 推导 |
|---|---|
| 含 经验不限 / 在校生 / 应届生 之一 | 包含校园岗位 |
| 只有年限档（1年以内、1-3年、3-5年、5-10年、10年以上） | 排除校园岗位（仍入库，面板可在"已排除"组查看原因） |
| 什么都没选（缺失即无限制） | 包含 |

只有用户明确说"我要看/不看校园岗"时才写 `include`/`exclude`。切换会生成新配置版本，`match` 会显示人数差异。

## 三个必须记录的默认

- 城市未限定：`profile.targets.cities` 为空数组，面板显示"未限定城市"。
- 经验范围未选：策略不发服务端经验筛选，`scoring.experience_allowlist` 不写，`campus_policy=auto` 推导为包含；面板显示"未限定经验"。
- 学历未提：不加学历排除；面板对硕士/博士岗位不做任何标记。

## 对"不会手写代码"这类陈述的处理

只影响岗位偏好（例如降低纯编码岗的分）和准备建议；不允许据此自动编造"可胜任"技能，也不允许在简历建议第一版里把未证实的能力写成经历。原话写进 `profile.notes`。scoring 规则的理由只写"用户偏好"或"待 JD 核验"，不推断面试形式。

## 访谈结束时输出

1. `profile.json` 候选 → `where-my-job validate profile F`
2. `scoring.json` 候选 → `where-my-job validate scoring F`
3. 首次策略（1 关键词 × 1 城 × 1 页）→ `where-my-job validate strategy F`。放在数据目录的 `strategies/first-page.json` 只是习惯命名，`--strategy` 接受任意路径
4. 用两三句话向用户复述画像要点（方向、城市、经验范围、排除规则），再用一道选择题确认："就按这个开始 / 我要改"。每次改画像都换一个新的 `profile_revision`。
